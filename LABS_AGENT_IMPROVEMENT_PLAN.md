## Professional Copy Standard

Every client-facing draft must:

1. Sound specific to this offer, audience, brand, and stage of awareness.
2. State a clear promise without inventing proof.
3. Use one unambiguous primary action and CTA vocabulary.
4. Turn features into concrete buyer meaning.
5. Handle real objections using approved evidence.
6. Avoid empty phrases such as “unlock,” “elevate,” “transform your journey,” “game-changing,” and “take your business to the next level” unless the client explicitly owns that language.
7. Avoid explaining the funnel, website, strategy, or copywriting process to the end customer.
8. Read like finished copy, not an outline, recommendation, or AI summary.
9. Surface missing evidence instead of smoothing it over with generic prose.
10. Require a human decision before publication or client delivery.

## Batch 2 — Governed Copy → Wireframe → Development Workflow

Source: User request on 25 July 2026 to prevent random AI and filler across copy, wireframes, and development plans.

### Governing Rule

No stage may silently invent or reinterpret the strategy. Every artifact must cite the approved inputs and version it inherited. If a required decision is missing, the system must show `Needs input` rather than completing the gap with plausible-sounding filler.

### Stage Gates

- [ ] **1. Create the verified evidence pack**
  - [ ] Collect approved discovery answers, live website evidence, brand guidelines, existing approved copy, product or service facts, audience information, proof, constraints, and required actions.
  - [ ] Label every source as `Approved`, `Verified`, `Client note`, `Inference`, or `Missing`.
  - [ ] Exclude unrelated client data and unapproved AI output.
  - [ ] Gate: do not begin strategy when the audience, offer, desired outcome, or business objective is unknown.

- [ ] **2. Approve the strategic brief**
  - [ ] Define the business goal, target audience, awareness stage, primary problem, desired outcome, offer, differentiator, proof, objections, conversion action, voice, and constraints.
  - [ ] Require one primary conversion goal and one primary CTA phrase.
  - [ ] Record unresolved decisions as questions with an owner; do not turn them into assumptions.
  - [ ] Gate: a human approves the brief version before copy generation.

- [ ] **3. Approve the content and journey architecture**
  - [ ] Define the page or funnel sequence and the job of every page.
  - [ ] Define the purpose, audience question, message, proof requirement, and CTA for every section.
  - [ ] Remove sections that do not advance understanding, trust, or action.
  - [ ] Gate: every proposed section must trace to the strategic brief.

- [ ] **4. Generate professional copy**
  - [ ] Draft from the approved strategic brief and content architecture—not directly from a URL or a one-line prompt.
  - [ ] Produce complete copy fields for each section, including headline, supporting copy, proof, objections, and CTA where applicable.
  - [ ] Attach source references and flag unsupported claims as `Needs approval`.
  - [ ] Run the editorial pass for specificity, voice, clarity, persuasion, repetition, filler, claim safety, and CTA consistency.
  - [ ] Gate: a human approves a named copy version before wireframing.

- [ ] **5. Build a content-led wireframe**
  - [ ] Generate layout from the approved copy version and section purposes.
  - [ ] Use real approved copy in the wireframe; do not replace it with lorem ipsum or newly generated alternatives.
  - [ ] Annotate hierarchy, component intent, proof placement, CTA behavior, responsive priority, and interaction needs.
  - [ ] Treat the wireframe as spatial strategy, not decoration.
  - [ ] Gate: flag copy that does not fit instead of silently truncating, rewriting, or shrinking it.

- [ ] **6. Create the development plan**
  - [ ] Generate the build plan from the approved strategy, copy version, and wireframe version.
  - [ ] Map every wireframe section to a component, content source, state, interaction, responsive rule, accessibility requirement, analytics event, and acceptance criterion.
  - [ ] Separate confirmed requirements from optional enhancements and future ideas.
  - [ ] Do not invent integrations, CMS fields, animations, or functionality not present in approved inputs.
  - [ ] Gate: every development task must trace to a wireframe element or explicit technical requirement.

- [ ] **7. Run cross-artifact consistency checks**
  - [ ] Confirm the audience, offer, promise, proof, CTA, terminology, and page order match across strategy, copy, wireframe, and development plan.
  - [ ] Detect missing sections, duplicated messages, altered claims, CTA drift, orphan components, and unsupported functionality.
  - [ ] Block handoff when an upstream artifact has changed without regenerating or reviewing downstream artifacts.

- [ ] **8. Complete human review and approval**
  - [ ] Present changes as a readable diff instead of asking reviewers to re-read the entire artifact.
  - [ ] Allow approval by artifact and version: `Strategy approved`, `Copy approved`, `Wireframe approved`, and `Development plan approved`.
  - [ ] Require a reason when requesting regeneration so the agent learns from an explicit correction.
  - [ ] Never publish, send to a client, or create build tasks from an unapproved version.

- [ ] **9. Preserve provenance and approved learning**
  - [ ] Save the client, project, artifact type, source versions, agent version, model, generation time, reviewer decision, and superseding version.
  - [ ] Store only human-approved voice and process guidance in client-scoped agent memory.
  - [ ] Keep reusable professional standards global while keeping private client facts and copy isolated.
  - [ ] Make every deliverable recoverable and comparable to the version that preceded it.
